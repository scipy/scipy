==========================
SciPy 2.0.0 Release Notes
==========================

.. note:: SciPy 2.0.0 is not released yet!

.. contents::

SciPy 2.0.0 is the culmination of X months of hard work. It contains
many new features, numerous bug-fixes, improved test coverage and better
documentation. There have been a number of deprecations and API changes
in this release, which are documented below. All users are encouraged to
upgrade to this release, as there are a large number of bug-fixes and
optimizations. Before upgrading, we recommend that users check that
their own code does not use deprecated SciPy functionality (to do so,
run your code with ``python -Wd`` and check for ``DeprecationWarning`` s).
Our development attention will now shift to bug-fix releases on the
2.0.x branch, and on adding new features on the main branch.

This release requires Python 3.12-3.15 and NumPy 2.0.0 or greater.


**************************
Highlights of this release
**************************


************
New features
************

``scipy.cluster`` improvements
==============================


``scipy.interpolate`` improvements
==================================

- Added `scipy.interpolate.make_lsq_ndbspline` to construct weighted
  least-squares tensor-product B-splines from scattered or rectilinear-grid
  data.
- The new ``clamp_values`` argument of `scipy.interpolate.make_lsq_spline` allows
  creating least-squares spline fits with predefined values at the endpoints of the
  interpolation interval: ``spl = make_lsq_spline(x, y, t, clamp_values=(42, None))``
  will satisfy ``spl(x[0]) == 42``.
- Batched ``y`` inputs are now supported in `scipy.interpolate.make_smoothing_spline`.


``scipy.linalg`` improvements
=============================
- The BLAS and LAPACK functions of `scipy.linalg.blas` and `scipy.linalg.lapack`
  are provided through C++ wrappers instead of the f2py tool. These were the last
  consumers of f2py and hence the f2py dependency is removed.
- `scipy.linalg.cython_blas` and `scipy.linalg.cython_lapack` were upgrade to
  Reference LAPACK version 3.9.1.
- The LAPACK function families ``?gesvdx``, ``?pbcon``, ``?lansb`` are now available in
  `scipy.linalg.lapack` namespace.
- The performance and memory usage of `scipy.linalg.null_space` has been improved for
  some tall/long matrices.


``scipy.ndimage`` improvements
==============================


``scipy.optimize`` improvements
===============================
- A new global optimizer, `scipy.optimize.biteopt` (BITmask Evolution OPTimization)
  was added. ``biteopt`` provides a competitive alternative for difficult global
  optimisation problems and showed strong benchmark performance.

``scipy.sparse`` improvements

``scipy.spatial`` improvements
==============================
- In `scipy.spatial.transform.rotation`, the performances of ``from_quat``, ``mul``,
  ``from_mrp``, and ``as_mrp`` have improved.
- Support for batched inputs was added to most `scipy.spatial.distance` functions
  mentioned in the Array API standard support section below.


``scipy.special`` improvements
==============================

- Added `scipy.special.mathieu_ce` and `scipy.special.mathieu_se`, which accept
  the angular argument in radians and return the function value and its
  derivative with respect to that same argument.
  Both functions are also available in `scipy.special.cython_special`.


``scipy.stats`` improvements
============================
- The accuracy of ``isf`` has been improved for ``powerlaw``, ``recipinvgauss``,
  ``rdist``, ``semicircular``, and ``moyal``.

***************************************
Array API standard support improvements
***************************************
- Array API standard support is now active by default, and the ``SCIPY_ARRAY_API``
  environment variable is no longer used.
- Array API support was added for the following functions in `scipy.spatial.distance`:
  ``braycurtis``, ``jensenshannon``, ``canberra``, ``chebychev``, ``num_obs_y``,
  ``jaccard``, ``is_valid_y``, and ``cosine``.
- Many functions in `scipy.special` now support mixed ``torch.tensor`` and Python
  scalar inputs. Backend delegation support has been substantially expanded to
  include: error functions, ellipsoidal harmonics, othogonal polynomial evaluation,
  spherical bessel functions, zeta functions, Legendre functions, Bessel functions,
  integrals of Bessel functions, Airy functions, Elliptic functions.


*******************
Deprecated features
*******************

- `scipy.special.mathieu_cem` and `scipy.special.mathieu_sem` are deprecated
  and will be removed in SciPy 2.2.0. Use `scipy.special.mathieu_ce` and
  `scipy.special.mathieu_se` instead, converting the input from degrees to
  radians. For example, replace ``mathieu_cem(m, q, x)`` with
  ``mathieu_ce(m, q, np.deg2rad(x))``. Both APIs return derivatives per radian,
  so the returned derivative requires no conversion.
  The corresponding legacy functions in `scipy.special.cython_special`
  are also deprecated.


********************
Expired Deprecations
********************
- The deprecated parameter ``precenter`` of `scipy.signal.lombscargle` has been removed.


******************************
Backwards incompatible changes
******************************
- The private ``_cpointer`` attribute on `scipy.linalg.blas` and `scipy.linalg.lapack`
  functions, an f2py implementation detail, is no longer present. Use
  `scipy.linalg.cython_blas` / `scipy.linalg.cython_lapack` for direct access from
  compiled code.
- The ``.pxd`` Cython headers for `scipy.linalg.cython_blas` /
  `scipy.linalg.cython_lapack` were updated to no longer contain any parameter names.
  All function arguments were already expected to be passed positionally, given that
  that's the natural way to call BLAS and LAPACK functions, and because in Fortran
  names aren't semantically meaningful and are regularly changed.
